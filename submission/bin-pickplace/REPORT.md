# Bin Pick-and-Place Engineering Report

## Submission Status

This repository contains a complete external Isaac Lab project, portable runtime assets, a registered manager-based environment and deterministic PLAY variant, keyboard teleoperation, validation tools, one HDF5 dataset with four successful human demonstrations, and four metric-complete three-view MP4 videos.

The implementation was validated with CPU unit tests and NVIDIA RTX 5070 Ti / Isaac Sim 5.1 integration runs. The four final videos were generated by replaying the recorded human actions; each replay triggered the task's target-aware success metric before the exporter committed the final MP4.

## A. Task Design

### A.1 Scene, Assets, and Coordinate Frames

The task is implemented as an external `ManagerBasedRLEnv`; it does not modify Isaac Lab core files. Each environment contains:

- one Franka Panda robot;
- the stock Seattle Lab table;
- one supplied white source bin and one supplied blue target bin;
- screwdriver, wrench, hammer, and pallet knife assets;
- two external RGB cameras and one wrist RGB camera.

World and environment frames are right-handed with +Z upward. Object poses exposed to the policy are environment-relative, which is equivalent to world coordinates for the single `env_0` evaluation setup. The Franka root frame is `panda_link0`. The blue-bin-relative target vector is computed by applying the inverse blue-bin rotation, rather than assuming that the bin is axis-aligned.

The packaged rigid-object roots are normalized to the geometric bottom. The Seattle tabletop is aligned near `z=0`, so both bins use a root height of `z=0.005 m`.

| Asset | Position (m) | Quaternion (wxyz) |
| --- | --- | --- |
| White bin | `(0.55, -0.30, 0.005)` | `(1, 0, 0, 0)` |
| Blue bin | `(0.55, 0.32, 0.005)` | `(1, 0, 0, 0)` |

The supplied white bin measures approximately `0.2976 x 0.1411 x 0.1295 m`, while the hammer is approximately `0.3086 m` long. Four non-overlapping tools cannot fit in one accessible layer at the original footprint. I therefore retained the supplied bin asset but scaled it by `(2.4, 2.4, 1.0)`. This preserves its height and appearance while providing physically valid reset poses and top-down finger approach corridors.

The final single-layer reset poses are:

| Tool | Root position (m) | Quaternion (wxyz) |
| --- | --- | --- |
| screwdriver | `(0.640262, -0.310392, 0.020)` | `(-0.6720588, 0, 0, 0.7404978)` |
| wrench | `(0.469094, -0.243457, 0.020)` | `(0.9429091, 0, 0, -0.3330501)` |

These poses were authored interactively in the complete Isaac Sim scene and then synchronized between the scene initial states and `TOOL_RESET_POSES`. Conservative rotated-AABB editor warnings are not used as the final collision decision because they include empty space around non-rectangular tools. The final layout was instead checked with local OBB containment tests, exact packaged PhysX collision geometry, 240 control steps of settling, and four successful human grasps.

The final runtime masses are:

### A.2 Reset and Language Conditioning

`reset_bin_pick_place` restores the Franka default joint pose with zero joint velocity, restores both bins, writes all four tool poses and zero root velocities, selects the episode target, clears the success streak, and generates the canonical instruction:

`Pick the <tool_name> from the white bin and place it in the blue bin.`

The training environment samples the four targets uniformly. The one-environment PLAY configuration is deterministic. During ordinary evaluation resets it cycles through the four targets reproducibly. During stock recording, target identity is tied to the number of successfully exported episodes, so a failed retry keeps the same target and the final order is:

`screwdriver -> wrench -> hammer -> pallet knife`.

The same target index drives the language instruction, observation one-hot, relative target observations, success metric, and failure metric. Success is false immediately after reset because all tools begin in the white bin and the blue bin is empty.

### A.3 Franka Action and IK Design

The public action is seven-dimensional:

`[delta_x, delta_y, delta_z, delta_rx, delta_ry, delta_rz, gripper]`

- Arm joints: `panda_joint.*` (seven arm joints).
- IK body: `panda_hand`.
- Controller: relative 6-DoF pose command with damped least-squares differential IK.
- Command frame: relative translation and rotation are interpreted in the Franka root/base frame (`panda_link0`) and mapped to world space by Isaac Lab.
- Translation scale: `(0.04, 0.04, 0.04) m` per normalized action.
- Rotation scale: `(0.15, 0.15, 0.15) rad` per normalized action.
- TCP offset: `(0, 0, 0.107) m` from `panda_hand`.
- Gripper: one binary input; each finger target is `0.04 m` when open and `0.0 m` when closed.

The `0.107 m` TCP offset follows the validated Isaac Lab Franka manipulation configuration and places the command point near the physical finger grasp plane rather than at the hand-link origin. This makes translational commands correspond to the location used to approach and hold a tool.

The registered keyboard device uses base sensitivities of `0.30` translation and `0.25` rotation before Action Manager scaling. At sensitivity `1.0`, a held translation key produces approximately `0.012 m` per 30 Hz control step, or a nominal command speed of `0.36 m/s`. Sensitivity can be raised for free-space travel and reduced for final alignment without changing the environment's 7D action contract.

The stock relative IK action recomputes its desired pose from the measured TCP every frame. Under load, a small elastic deflection can therefore become the next desired pose and accumulate into whole-arm sag. `HoldLastPoseDifferentialIKAction` preserves normal relative commands when motion input is present but holds the previous TCP target when the motion command is zero. The target is reinitialized from the measured pose after reset.

Shoulder and forearm stiffness are `800`, damping is `80`, and the physical Franka effort limits remain the stock `87/12 N.m`. A load probe applied the `0.65 kg` hammer equivalent (`6.377 N`) plus a `0.956 N.m` eccentric torque directly to `panda_hand`. Over six seconds, the final configuration limited maximum vertical drop to `5.032 mm`, maximum orientation error to `0.012475 rad`, and desired-target drift to `0 mm`.

Physics runs at 120 Hz with control decimation 4, so action, rendering, observations, and all three cameras remain synchronized at 30 Hz. Franka solver iterations are `32/4`; supplied tools use `contact_offset=0.003 m` and `rest_offset=0`. CPU PhysX enables CCD. Isaac Sim 5.1 does not support CCD in the CUDA dynamics pipeline, so GPU runs use four 120 Hz substeps per action as the supported anti-tunnelling measure.

Collision geometry is selected by shape rather than forcing every asset into one representation:

- the Franka retains the official instanceable collision asset;
- the screwdriver uses an analytic capsule for the thin shaft and a convex hull for the handle;
- the wrench uses a sparse SDF (`resolution=256`, `subgrid=6`) to retain its open jaw and concavities;
- the hammer and pallet knife use convex decomposition.

No scripted pick/grasp/place controller exists inside the environment. It only consumes actions supplied by the operator or a downstream policy.

## B. Task Metric Design

### B.1 Formal Success Definition

Only the instructed target tool is evaluated. Let its local bounding-box corners be `c_i`, world pose be `(p_t, q_t)`, linear/angular velocities be `(v, w)`, the blue-bin pose be `(p_b, q_b)`, gripper opening be `g`, and TCP position be `p_e`. Each corner is transformed into the blue-bin frame:

`c_i^b = q_b^-1 * (p_t + q_t * c_i - p_b)`

A control step is valid only when all of the following hold:

1. **Inside:** all eight transformed tool corners are strictly inside the conservative blue-bin interior: `x in (-0.205, 0.205)`, `y in (-0.135, 0.135)`, and `z in (0.000, 0.235)`.
2. **Settled:** `||v|| < 0.05 m/s` and `||w|| < 0.50 rad/s`.
3. **Released:** summed finger opening `g > 0.055 m` and `||p_t - p_e|| > 0.10 m`.
4. **Persistent:** the other three conditions hold for ten consecutive 30 Hz control steps, approximately `0.333 s`.

Using all eight corners prevents a long tool from balancing across the rim while its root lies near the bin center. The strict local-frame bounds continue to work if the blue bin is rotated.

### B.2 Threshold Rationale

- The blue-bin XY bounds are inset from the measured shell, providing tolerance for collision and rendering approximations.
- A CUDA contact probe measured the lowest rotated screwdriver corner at approximately `z=0.00285 m` when physically settled on the bin floor. Therefore `z>0` accepts floor contact while still rejecting penetration below the measured shell bottom.
- `0.05 m/s` corresponds to less than approximately `1.7 mm` of translation per control step.
- `0.50 rad/s` corresponds to less than approximately `0.017 rad` (about one degree) per control step; the ten-frame persistence condition filters short transients.
- `0.055 m` means both fingers are visibly open while remaining below the `0.08 m` summed mechanical maximum.
- `0.10 m` is comparable to the TCP offset and requires the hand to withdraw from the released object.
- Ten consecutive frames reject a bouncing or momentarily valid placement without making manual operation unreasonably slow.

### B.3 False-Positive Probes

CPU unit tests and live-scene CUDA probes cover the required adversarial cases:

- a wrong tool in the blue bin while the target remains in the white bin: rejected;
- the target inside the bin but still held by a closed gripper: rejected;
- target linear speed of `0.10 m/s`: rejected;
- excessive angular motion: rejected;
- a tool spanning the rim: rejected by all-corner containment;
- only nine consecutive valid frames: rejected;
- the tenth consecutive valid frame: accepted.

### B.4 Failure and Timeout

Failure is target-specific and represents an unrecoverable loss: the target root is below `z=-0.10 m` or outside a `1.25 m` horizontal workspace radius. Timeout is a separate `time_out=True` termination at 120 seconds. A timeout is therefore recorded as truncation rather than task failure.

### C.3 Downstream Use and Limitations

The environment and recordings are ready for language-conditioned behavioral cloning and multi-view imitation-learning experiments. Adding a tool requires packaging its portable asset, measuring bounds, defining a non-overlapping reset pose, extending target identity, and collecting a new demonstration. Replacing a bin requires remeasuring its local interior and reset geometry. Replacing the robot requires new joint selections, IK body/TCP, action scales, gripper mapping, and wrist mount. Adding a camera requires a stable observation key, calibrated intrinsics/extrinsics, synchronized update period, and recorder/exporter mosaic changes.

Current limitations are:

- no reward function is defined, so the project does not claim reinforcement-learning readiness;
- only RGB is configured; depth and semantic segmentation are outside the assignment scope;
- bins are kinematic rigid objects;
- the white-bin XY scale is 2.4 to meet the measured capacity and grasp-access requirements;
- all-corner OBB containment is conservative rather than exact mesh-volume containment;
- `demo_1` is close to the timeout and contains a long initial idle segment; and
- strict full-state replay can show small GPU-dependent velocity differences, while action replay and metric results remain valid.

### D.3 AI Suggestion I Corrected or Rejected

An important correction concerned the load-holding failure. The initial AI interpretation focused on the gripper losing the tool and suggested changing grasp/contact parameters. I rejected that diagnosis because the tool remained secured between the fingers; the entire Franka arm was drifting downward. This distinction changed the solution from increasing gripper friction or hiding the symptom with lighter objects to preserving the IK TCP target under zero input, tuning arm joint stiffness/damping within the original effort limits, and applying a measured external load to the hand.

I accepted the revised approach only after the load probe showed target drift reduced from approximately `197 mm` to `0 mm` and six-second maximum hand drop limited to `5.032 mm` under the heaviest-tool equivalent force and eccentric torque.
